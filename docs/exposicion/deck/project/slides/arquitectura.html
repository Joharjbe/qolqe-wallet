PUNTO 1 · ARQUITECTURA · OBS. 1c

Del Gherkin a la evidencia

9 · Entrega final · Pruebas de Qolqe

Esta lámina responde la primera observación: que quede clara la arquitectura del proyecto de automatización, API y web. Se lee de izquierda a derecha, columna por columna. QUÉ: el Gherkin dice qué se prueba: 276 escenarios de API en features/*.feature y 58 web en features/web/. El contrato, CP-T04, no pasa por Gherkin: parte de /openapi.json. TRADUCE: los pasos. pytest-bdd en Python para la API, con 266 pasos, y playwright-bdd en TypeScript para la web, con 139. Schemathesis, también en Python, lee el OpenAPI de Qolqe y genera los casos. HABLA: lo que habla con Qolqe. En la API, el cliente Sesiones, hecho con httpx, que guarda el token de cada usuario; en la web, los Page Objects y sus 5 componentes, así que ningún paso tiene un localizador. El contrato manda directo las peticiones que generó. SISTEMA: Qolqe sin cambios, como caja negra, con una base SQLite por suite para que una suite no ensucie a la otra. UNE: cada suite deja su JUnit. La API, con su reporte HTML con las peticiones; la web, con traza, captura y video; el contrato, con su HTML. Las partes comparten artefactos, no código: el Gherkin con sus etiquetas @HU @CA @CP @DEF, la API de soporte y el formato JUnit. Por eso el JUnit es el punto de unión: con él, trazabilidad.py arma la matriz, que se ordena por esas etiquetas, y el historial que se publica en Pages; y Kiwi TCMS importa los Test Runs desde mi máquina. La franja azul es lo que corre en GitHub Actions: las tres primeras filas. La franja punteada va a mano: el rendimiento tiene su propio requerimiento, k6 en JavaScript con 8 escenarios escritos a mano, sesiones completas por HTTP contra Qolqe en un contenedor Docker de 1 CPU y 1 GB, fuera del pipeline. Su evidencia no pasa por el JUnit: queda versionada en el repositorio. Si pregunta por qué dos lenguajes: cada capa usa el runner que enseña la clase. La clase 10 enseña pytest con pytest-bdd y Schemathesis, en Python, que además es el lenguaje de Qolqe; la clase 11 enseña Playwright con playwright-bdd, en TypeScript, y su runner trae integradas las repeticiones, los reintentos y las trazas. El costo es real y está escrito: dos gestores de dependencias y los usuarios de prueba repetidos en las dos suites.

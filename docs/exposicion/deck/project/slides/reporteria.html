El reporte queda publicado al terminar el último job

CON EVIDENCIA O SIN EVIDENCIA, A ELECCIÓN

Al lanzar el workflow a mano se elige con-imagenes o sin-imagenes. Con imágenes, cada prueba web guarda captura, video y traza, y cada caso de API sus peticiones. En los push normales va sin imágenes, porque el sitio con evidencia completa pesa casi 200 MB.

TRES FORMATOS, CADA UNO PARA ALGO

HTML para personas: pytest-html con las peticiones; Schemathesis, que con imágenes suma el HAR; Playwright, con traza y video. JUnit XML para las herramientas: lo leen la matriz y Kiwi. Resumen de cada job en Actions.

QUÉ HAY EN EL SITIO PUBLICADO

Portada con el veredicto, reportes HTML, matriz, evidencias por caso, historial de los runs de main desde el #17 (guarda hasta 30 y dibuja los últimos 15) y, desde esta entrega, la Parte 3: veredicto por umbral, comparativo y gráficos de las ocho corridas.

EL DETALLE QUE FALTABA

El job que publica ahora es el último del run y deja en el resumen los enlaces al sitio, a la Parte 3 y a las evidencias.

16 · Entrega final · Pruebas de Qolqe

Este punto responde la observación 2b, elegir si el reporte va con evidencia o sin ella, y la del laboratorio S11, que pedía profundizar en la reportería de la herramienta y sus opciones. El enunciado también pide que el reporte esté visible al terminar el último job. Lo de la evidencia es una entrada del workflow. Con imágenes, cada prueba web guarda captura, video y traza, y cada caso de API guarda sus peticiones. Sin imágenes, solo de los fallos. Los push normales van sin imágenes porque el sitio con evidencia completa pesa casi 200 megas, el run deja unos 416 entre todos sus artefactos, y los artefactos de GitHub caducan. Sobre la reportería de cada herramienta: uso los tres formatos que vimos en la clase 12, y cada uno tiene un lector distinto. El HTML es para personas: el de pytest-html trae las peticiones de cada caso, el de Schemathesis con imágenes suma el HAR, y el de Playwright trae la traza paso a paso y el video. El JUnit XML es para las herramientas: con él se arman la matriz y los Test Runs de Kiwi. Y el resumen de cada job queda en la página del run. Sobre «al terminar el último job» había un detalle que no estaba bien: el job que publica terminaba último por casualidad, y en los runs #17 y #18 el orden ya se había invertido: gestion-casos terminó después que publicar. Ahora depende explícitamente del anterior, así que es el último de verdad, y deja en el resumen los enlaces al sitio. El historial guarda hasta 30 runs y la página dibuja los últimos 15. Empezó en el run #17: al 18 de noviembre tenía 5 columnas, y cada run nuevo de main suma una. Y desde esta entrega el sitio tiene la Parte 3: el veredicto por umbral, el comparativo entre escenarios y los gráficos de las ocho corridas.

PUNTO 6 · REPORTERÍA · OBS. 2b Y LAB S11

El último job publica el reporte

16 · Entrega final · Pruebas de Qolqe

Este punto responde la observación 2b, elegir si el reporte va con evidencia o sin ella, y la del laboratorio S11, que pedía profundizar en la reportería de la herramienta y sus opciones. El enunciado también pide que el reporte esté visible al terminar el último job. Empiezo por eso, arriba a la izquierda, porque había un detalle que no estaba bien: el job que publica terminaba último por casualidad, y en los runs #17 y #18 el orden ya se había invertido: gestion-casos terminó después que publicar. Ahora publicar depende explícitamente del anterior, así que es el último de verdad, y deja en el resumen del run los enlaces al sitio, a la Parte 3 y a las evidencias. Lo que publica es el sitio de la derecha: la portada con el veredicto, los reportes HTML, la matriz, las evidencias por caso, el historial de los runs de main y, desde esta entrega, la Parte 3: el veredicto por umbral, el comparativo entre escenarios y los gráficos de las ocho corridas. El historial guarda hasta 30 runs y la página dibuja los últimos 15. Empezó en el run #17: al 18 de noviembre, con el run #28, tenía 7 entradas, y cada run nuevo de main suma una. El interruptor es una entrada del workflow: al lanzarlo a mano se elige con-imagenes o sin-imagenes. Con imágenes, cada prueba web guarda captura, video y traza, y cada caso de API guarda sus peticiones. Sin imágenes, solo de los fallos. Los push normales van sin imágenes porque el sitio con evidencia completa pesa casi 200 megas, el run deja unos 416 entre todos sus artefactos, y los artefactos de GitHub caducan. Sobre la reportería de cada herramienta, abajo a la derecha: uso los tres formatos que vimos en la clase 12, y cada uno tiene un lector distinto. El HTML es para personas: el de pytest-html trae las peticiones de cada caso, el de Schemathesis con imágenes suma el HAR, y el de Playwright trae la traza paso a paso y el video. El JUnit XML es para las herramientas: con él se arman la matriz y los Test Runs de Kiwi. Y el resumen de cada job queda en la página del run, en Actions.

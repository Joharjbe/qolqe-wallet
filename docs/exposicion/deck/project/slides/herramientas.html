8 · Entrega final · Pruebas de Qolqe

Esta lámina responde la observación que me hicieron dos veces: que las herramientas sean complementarias y que su elección esté sustentada. La idea que las ordena es que cada una responde una pregunta que las otras no responden, y la última columna dice frente a qué la elegí. pytest-bdd prueba los casos que yo diseñé desde los criterios, con el mismo Gherkin que la web; Postman con Newman no lee Gherkin y Newman ya no recibe actualizaciones. Schemathesis genera casos desde el contrato, así que encuentra lo que a mí no se me ocurrió: así salieron cuatro defectos; eso es complementario, no redundante. Playwright prueba lo que solo existe en la pantalla; elegí Playwright y no Cypress porque un caso necesita dos navegadores a la vez. k6 responde si aguanta la carga: el requerimiento da la carga como sesiones por hora, que es una tasa de llegada, y el modelo abierto de JMeter es experimental. GitHub Actions corre todo sin un servidor propio. Y Kiwi no ejecuta nada: registra cada corrida. Abajo está la regla que uso para decidir dónde va cada caso, que es de la clase 11: si se puede comprobar por API, se prueba por API, porque es más rápido y más estable. La web se reserva para lo que de verdad necesita el navegador. Si pregunta por qué dos lenguajes: cada suite usa el runner que enseña la clase, pytest en Python para la API y Playwright Test en TypeScript para la web; lo que comparten es el Gherkin y el JUnit, no código. La comparación completa de k6 con JMeter, Gatling, Locust, Artillery y Taurus está en el informe de rendimiento.

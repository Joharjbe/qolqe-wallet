Esta lámina responde la observación que me hicieron dos veces: que las herramientas sean complementarias y que su elección esté sustentada. Se lee por capas, de izquierda a derecha: cuatro herramientas ejecutan, una automatiza y una registra. Cada tarjeta tiene arriba la pregunta que responde, en verde por qué la elegí y tachada la alternativa que descarté. Ninguna responde la pregunta de otra: por eso son complementarias, no redundantes. pytest-bdd con httpx, en Python, responde si la regla de negocio se cumple. Lee el mismo Gherkin que la web y un hook deja cada DEF como fallo esperado estricto. Postman con Newman no lee Gherkin y Newman ya no recibe actualizaciones. Playwright con playwright-bdd, en TypeScript, responde si el usuario puede hacerlo en la pantalla. Espera solo y da traza y video. Lo elegí y no Cypress porque CP-NW18 necesita dos sesiones a la vez, y Cypress no controla dos navegadores. Schemathesis responde si la API cumple el contrato que promete. Genera los casos desde el OpenAPI, así que encuentra lo que a mí no se me ocurrió: así salieron cuatro defectos, DEF-05, 06, 08 y 29; de esos cuatro, dos solo los detectó el contrato y los otros dos también los detectó otra suite. Dredd quedó archivado en noviembre de 2024. k6 responde si aguanta la hora punta y hasta dónde crece. El requerimiento da la carga como sesiones por hora, que es una tasa de llegada: eso es un modelo abierto. El modelo abierto de JMeter es experimental y JMeter termina con 0 aunque haya fallas. k6 corre a mano, fuera del pipeline. GitHub Actions responde si todo sigue cumpliendo después de cada cambio: ocho jobs, de lo barato a lo caro, sin un servidor propio. Jenkins exige mantener un servidor y sus agentes. Kiwi TCMS no ejecuta nada: importa el JUnit y registra cómo le fue a cada caso en cada corrida, con su trazabilidad. Lo comparé con ocho herramientas en el punto 7. La flecha de arriba, API antes que pantalla, es la regla de niveles, de la clase 11: lo que se puede comprobar por API va por API, que es más rápido y más estable; la web se reserva para lo que solo existe en la pantalla. Si pregunta por qué dos lenguajes: cada suite usa el runner que enseña la clase, pytest en Python para la API y Playwright Test en TypeScript para la web; lo que comparten es el Gherkin y el JUnit, no código. La comparación completa de k6 con JMeter, Gatling, Locust, Artillery y Taurus está en el informe de rendimiento.
